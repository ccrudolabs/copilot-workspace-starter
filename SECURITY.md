# Security Policy

## Alcance

Este repositorio publica material educativo, laboratorios, ejemplos y un sitio estatico de estudio para GH-300 y GitHub Copilot.

## Reporte de vulnerabilidades

Si detectas una exposicion de secretos, credenciales, informacion sensible, enlaces rotos con riesgo de seguridad o contenido que pueda inducir a una mala practica, reportalo de forma privada al autor por LinkedIn:

- https://www.linkedin.com/in/carloscrudo/

No abras un issue publico con secretos reales, tokens, claves o datos privados.

## Secretos y ejemplos

Los laboratorios que explican Secret Scanning usan placeholders seguros. No se deben publicar credenciales reales ni tokens activos en issues, pull requests, commits o archivos de ejemplo.

## Buenas practicas esperadas

- No incluir claves reales en ejemplos.
- No adjuntar informacion sensible de empresas o clientes.
- Usar placeholders claros para credenciales simuladas.
- Validar enlaces y referencias antes de proponer cambios.
- Mantener trazabilidad de cambios mediante pull requests.
