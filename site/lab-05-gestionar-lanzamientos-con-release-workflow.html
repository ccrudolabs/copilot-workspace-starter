Laboratorio 05: Gestionar Releases con Flujo de Trabajo

Lab 05: Gestionar lanzamientos de software con un flujo de trabajo basado en lanzamientos en GitHub

Objetivo:

Imagina que formas parte de un equipo de desarrollo de software trabajando en un proyecto Eso requiere actualizaciones y lanzamientos regulares. Para gestionar tu software De forma eficiente, decides implementar un flujo de trabajo basado en lanzamientos usando GitHub. Este flujo de trabajo te ayuda a gestionar el sistema de versiones y software iteraciones efectivas, asegurando que cada versión se registre y Los problemas se abordan de manera controlada.

En este laboratorio práctico,

Crear un repositorio: Crear un repositorio llamado flujo de trabajo basado en liberación de habilidades para servir de base para tu flujo de trabajo basado en lanzamientos.

Implementar el versionado: Explora los conceptos de versionado y el Importancia de hacer seguimiento de las iteraciones del software.

Crea una versión beta: Sigue los pasos para crear una versión beta para la base de código actual, incluyendo etiquetado y publicación en GitHub.

Simula un escenario real: introduce un error en la base de código, simulando un escenario común para identificar y abordar problemas dentro del flujo de trabajo de liberación.

Ejercicio #1: Configurar un nuevo Repositorio (que sirva de base para el flujo de trabajo basado en lanzamientos)

Inicia sesión en tu cuenta de GitHub.

Navega hasta el siguiente enlace: https://github.com/skills/release-based-workflow

En este laboratorio crearás el repositorio usando una plantilla pública de "flujo de trabajo basado en liberación de habilidades".

Selecciona Crear un nuevo repositorio en el menú Usar esta plantilla.

Introduce los siguientes datos y selecciona Crear Repositorio.

Nombre del repositorio: flujo de trabajo basado en lanzamiento de habilidades

Tipo de repositorio: Público

Ejercicio #2: Crear una versión para la base de código actual

En este ejercicio, crearemos una versión para este repositorio en GitHub.

Las versiones de GitHub apuntan a un commit específico.

Los lanzamientos pueden incluir notas de lanzamiento en archivos Markdown y adjuntas binarios.

Nota: Antes de usar un flujo de trabajo basado en lanzamientos para un lanzamiento más grande, creemos una etiqueta y un lanzamiento.

Una vez creado el repositorio (en el Ejercicio #1), navega a Versiones en la barra lateral derecha de la página y haz clic en Crear una Nuevo lanzamiento.

Consejo: Para acceder a esta página, haz clic en la pestaña de Código en la parte superior de tu repositorio. Luego, busca la sección de Lanzamientos en la barra lateral de la Derecha.

En la página de Lanzamientos/Etiquetas apunta lo siguiente:

Mantén el objetivo como principal

En el campo Elegir una etiqueta, especifica un número.

En este caso, usa v0.9 y selecciona Crear nueva etiqueta v0.9 al publicar

Dale un título al lanzamiento, como Primera versión beta

Nota: También podrías dar una breve descripción al comunicado.

Desplázate hacia abajo por la página para seleccionar la casilla de verificación junto a Establecer como pre-lanzamiento, ya que representa una versión beta y haz clic en Publicar lanzamiento.

Ejercicio #3: Introducir un error (que se corregirá más adelante)

Para preparar el terreno para más adelante, ahora añadimos un error que corregiremos como parte del flujo de trabajo de lanzamiento en pasos posteriores. Una rama "update-text-colors" es ya creado en el repositorio (creado en el Ejercicio #1) para ti, así que Vamos a crear y fusionar una solicitud pull con esta rama.

En la barra principal de navegación, haz clic en la pestaña de Pull requests.

En la página siguiente, haz clic en Nueva solicitud de tirada.

En la página Comparar cambios, selecciona lo siguiente y haz clic en Crear solicitud pull,

base: release-v1.0 y

Comparar: actualizar-colores-texto.

En la página Abrir una solicitud de tirada, introduce lo siguiente y luego haz clic en Crear solicitud pull.

Añadir un título: Establecer el título de la pull request en Estilo de texto actualizado del juego

Añade una descripción: ## Descripción: Actualizado el color del texto del juego a verde

En la página de Estilo de texto actualizado #1 haz clic en Unir pull Solicitar, luego Confirmar la página.

En la siguiente página, elimina la rama recién creada haciendo clic en el botón Eliminar rama.

Espera unos 20 segundos mientras GitHub Actions actualiza automáticamente la página.

Resumen:

Ahora has adquirido experiencia práctica en establecer y gestionar un flujo de trabajo basado en lanzamientos, mejorando tu capacidad para rastrear versiones, gestionar lanzamientos y resolver errores de forma eficiente.
