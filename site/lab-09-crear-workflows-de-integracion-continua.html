Laboratorio 09: Flujos de Trabajo para Integración Continua (CI)

Lab 09: Crea flujos de trabajo para usar la Integración Continua (CI) en tus proyectos

Objetivos:

Imagina que estás trabajando en un proyecto de software donde mantener Los altos estándares de calidad son fundamentales. Para asegurar que tu código se mantenga robusto y libre de errores, decides implementar Continuo Integración (CI) usando GitHub Actions. La CI ayuda a automatizar el proceso de Ejecutar pruebas y comprobar la calidad del código cada vez que se realizan cambios en La base de código. Creando flujos de trabajo de CI, puedes eliminar automáticamente pelusa Markdown, ejecuta pruebas y recibe feedback inmediato sobre el código calidad, asegurando que tu proyecto cumpla con sus estándares de calidad de forma constante.

En este laboratorio práctico, tú deberás:

Crea un flujo de trabajo de prueba: Configura un flujo de trabajo de acciones en GitHub diseñado específicamente para filtrar archivos Markdown y comprobar Problemas de formato.

Configurar y actualizar el flujo de trabajo: Practica la configuración del flujo de trabajo para definir los trabajos y pasos necesarios para el linting automatizado, y actualizarlo según sea necesario para mejorar su funcionalidad.

Crea una solicitud de tirada: Integra los cambios creando una solicitud de tirada request, permitiéndote probar el flujo de trabajo del CI y observar cómo automatiza los controles de calidad.

Analiza los resultados del flujo de trabajo de CI para entender cómo informa y garantiza la calidad del código.

Ejercicio #1: Crea un nuevo repositorio a partir de una plantilla pública

Navega hasta el siguiente enlace: https://github.com/skills/test-with-actions

En este laboratorio crearás el repositorio usando una plantilla pública "prueba de habilidades con acciones".

Selecciona Crear un nuevo repositorio en el menú Usar esta plantilla.

Introduce los siguientes datos y selecciona Crear Repositorio.

Nombre del repositorio: prueba de habilidades con acciones

Tipo de repositorio: Público

Ejercicio #2: Añadir un flujo de trabajo de prueba

Navega a la pestaña Acciones en el repositorio creado hace un tiempo.

En Acciones en la barra lateral izquierda, selecciona Nuevo flujo de trabajo.

En la página Elige un flujo de trabajo, navega a "Simple flujo de trabajo" y haz clic en Configurar.

En la siguiente página, cambia el nombre a tu flujo de trabajo como ci.yml y actualización El flujo de trabajo eliminando los dos últimos pasos.

Añade el siguiente código al final del flujo de trabajo y haz clic en Confirmar cambios en la esquina superior derecha.

name: Run markdown lint

run: |

npm install remark-cli remark-preset-lint-consistent

npx remark . --use remark-preset-lint-consistent

Nota: Por favor, asegúrate de que el fragmento de código añadido al flujo de trabajo esté correctamente indentado

En la ventana de Cambios de confirmación, selecciona Crear una nueva rama para este commit y comienza una solicitud de tirada.

Una vez que se selecciona crear una nueva rama para este commit y iniciar una pull request, la ventana de Cambios de Commit cambia a la ventana de Proponer cambios. Ahora haz clic en Proponer cambios.

En la siguiente página de Abrir una solicitud pull, haz clic en Crear pull Petición.

Espera 20 segundos y luego actualiza esta página para analizar el resultados.
