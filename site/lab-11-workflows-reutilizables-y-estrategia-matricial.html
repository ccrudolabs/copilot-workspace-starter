Laboratorio 11: Workflow Reutilizable y Estrategia Matricial

Laboratorio 11: Hacer reutilizable un flujo de trabajo y utilizar una estrategia matricial para ejecutar múltiples versiones de nodo

Objetivos:

Imagina que gestionas múltiples repositorios dentro de un proyecto que Comparte flujos de trabajo comunes para tareas como construir, probar y desplegar. Para evitar redundancia y mantener la coherencia entre estos repositorios, decides implementar flujos de trabajo reutilizables usando GitHub Actions. Por Utilizando el desencadenante de llamadas al flujo de trabajo, puedes centralizar tu flujo de trabajo configuraciones, asegurando que los cambios se realicen en un solo lugar y se aplica automáticamente en todos los repositorios relevantes. Además, Aprovecharás estrategias matriciales para probar tus flujos de trabajo con múltiples versiones de Node.js, mejorando la compatibilidad y la escalabilidad.

En este laboratorio práctico, tú deberás:

Utiliza el disparador workflow_call para que tus flujos de trabajo sean reutilizables en todos los aspectos múltiples repositorios, reduciendo la redundancia de configuración.

Navega a tu repositorio, actualiza el archivo de flujo de trabajo para incluir el workflow_call activar y comprometer los cambios.

Crea pull requests para comparar los cambios y las excepciones.

Ejercicio #1: crear un nuevo repositorio.

Navega hasta el siguiente enlace: https://github.com/skills/reusable-workflows

En este laboratorio crearás el repositorio usando una plantilla pública "flujos de trabajo reutilizables de habilidades".

Selecciona Crear un nuevo repositorio en el menú Usar esta plantilla.

Introduce los siguientes datos y selecciona Crear Repositorio.

Nombre del repositorio: Flujos de trabajo reutilizables por habilidades

Tipo de repositorio: Público

Ejercicio #2: Añadir un desencadenante workflow_call a un flujo de trabajo

En la página de inicio del repositorio recién creado, navega a la pestaña de Código.

Desde el desplegable de la rama principal, selecciona rama de flujo de trabajo reutilizable.

Después de cambiar la rama, navega a la carpeta .github/workflows/ y luego selecciona reusable-workflow.yml archivo.

En el editor de archivos reusable-workflow.yml selecciona Editar en lugar.

Sustituye el disparador de workflow_dispatch evento por el de workflow_call evento y haz clic en Confirmar cambios.

Nota: Sustituye el bloque de código de la Línea #3 a la Línea #8 por el que está abajo

on:

workflow_call:

inputs:

node:

required: true

type: string

En la ventana de Confirmar cambios, haz clic en Confirmar cambios.

Ejercicio #3: Crea una pull request para ver los cambios realizados en el ejercicio anterior

Selecciona la pestaña de solicitudes pull y luego haz clic en Nueva solicitud pull (Nuevo pull request).

En la página de Comparar cambios, establece la base como principal y compara como flujo de trabajo reutilizable.

En la página de Abrir una solicitud pull haz clic en Crear solicitud pull (Crear solicitud pull).

Espera 20 segundos a que se ejecuten las acciones y revisa los resultados.
