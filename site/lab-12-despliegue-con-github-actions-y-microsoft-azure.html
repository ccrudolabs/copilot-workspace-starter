Laboratorio 12: Despliegue en Microsoft Azure con GitHub Actions

Laboratorio 12: Creación de flujos de despliegue usando GitHub Actions y Microsoft Azure

Objetivos:

Imagina que gestionas un proyecto de software con despliegue complejo requisitos que involucran múltiples entornos, incluyendo la puesta en escena y producción. Para agilizar tu proceso de despliegue y garantizar Consistencia, decides automatizarlo usando GitHub Actions y Microsoft Azure. Configurando los flujos de trabajo de despliegue, puedes configurar disparadores basados en etiquetas aplicadas a las pull requests, que se encargarán Poner en marcha los entornos, desplegarse en fases y desmontar Entornos automáticos. Este enfoque ayuda a mantener la eficiencia y reduce la intervención manual en la cadena de despliegue.

En este laboratorio práctico, tú deberás:

Configura flujos de trabajo para crear y configurar automáticamente entornos usando recursos de Azure cuando se aplica una etiqueta específica a una pull Petición.

Configura tareas de despliegue dentro de los flujos de trabajo para que se desplieguen automáticamente Tu proyecto a un entorno de puesta en escena al recibir el documento adecuado etiqueta.

Ejercicio 1: Crear un nuevo repositorio

Navega hasta el siguiente enlace: https://github.com/skills/deploy-to-azure

En este laboratorio crearás el repositorio usando una plantilla pública skills-deploy-to-Azure

Selecciona Crear un nuevo repositorio en el menú Usar esta plantilla.

Introduce los siguientes datos y selecciona Crear Repositorio.

Nombre del repositorio: skills-deploy-to-Azure

Tipo de repositorio: Público

Ejercicio 2: Configurar permisos GITHUB_TOKEN

Al inicio de cada ejecución de flujo de trabajo, GitHub crea automáticamente un secreto GITHUB_TOKEN único para usar en tu flujo de trabajo. Tenemos que asegurarnos de que este token tenga los permisos requeridos.

En la página de inicio del repositorio recién creado, ve a Configuración > Acciones > General.

Desplázate hacia abajo hasta permisos de flujo de trabajo, activa permisos de lectura y escritura y haz clic en Guardar.

Nota: Esto es necesario para que el flujo de trabajo suba la imagen al registro de contenedores.

Ejercicio 3: Configurar un disparador basado en etiquetas

En la barra de navegación, ve a la pestaña Acciones

En la página de Acciones, haz clic en Nuevo flujo de trabajo en la navegación Paneles en el lado izquierdo.

En la página Elige un flujo de trabajo, busca "simple flujo de trabajo\" y haz clic en Configurar

Nombra tu flujo de trabajo deploy-staging.yml

En la página de edición, edita el contenido del archivo y elimina todo desencadenantes y trabajos. El archivo resultante se verá como se muestra a continuación.

name: Stage the app

on:

pull_request:

types: [labeled]

jobs:

build:

runs-on: ubuntu-latest

if: contains(github.event.pull_request.labels.*.name, 'stage')

Nota: Por favor, asegúrate de que el fragmento de código añadido esté correctamente indentado como se muestra en la captura de pantalla

Haz clic en el botón Comprometer cambios en la parte superior derecha de la página.

En la ventana de Cambios de confirmación, selecciona Crear una nueva rama para este commit y comienza una solicitud pull.

Nota: Compromete los cambios en la ventana de cambios en Proponer cambios.

Nombra la nueva rama como Flujo de trabajo de etapas y haz clic en Proponer cambios.

En la página siguiente de Abrir una solicitud pull haz clic en Crear pull Petición.

Espera 20 segundos a que se ejecuten las acciones y revisa los resultados.

Resumen:

Ahora has adquirido experiencia práctica automatizando flujos de trabajo de despliegue usando GitHub Actions, mejorando la eficiencia y fiabilidad de tu proceso de despliegue.
